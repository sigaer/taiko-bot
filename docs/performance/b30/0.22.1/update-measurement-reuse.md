# 中心 BXX 复用更新端测量（0.22.1）

中心 `taikob1`～`taikob50` 汇总图不再读取、还原或重新评分历史成绩。
复用既有 `daily-ability-v1-top20.json` / `daily-ability-v2-top20.json`，
不新增另一套私人缓存，不对存量成绩、历史和 Publication 做迁移或回填。
独立客户端的远端历史协议和独立趋势命令不在本次变更范围内。

## 对比语义

- 近30日增长：当前数值减去查询当日及之前29个自然日内最早的有效测量。
  新格式保留窗口首日第一次测量，避免当天后续更新覆盖基准。
  图上名称从“近30日区间”改为“近30日增长”，支持显示负值。
- 本次增长：当前六维、Rating 减去紧邻的上一次更新测量，同日多次更新也独立比较。
- NEW：当前 TopN 相对上一份 TopN 新进入的谱面；单曲提升比较同一谱面的 Rating。
  总 Rating 相同也检查榜单和六维，不依赖四舍五入后的显示值判断。
- 缺失对比信息时不显示对应变化，不将全部歌曲标为 NEW，不触发历史补算。

## 沿用现有测量所有者

华立、Hiroba 的 `save_userdata` 本来就调用 `daily_ability.capture_snapshot`。
本次直接复用该计算结果：默认 v2 Top20 的六维和 Rating 沿用原数值，
额外从同一批已计算结果中截取各维前50个数值及榜单谱面信息，不重新计算 v2 成绩。
同步接收器、非 Python 写入桥接器（含手动成绩）和 u0 物化也调用同一个所有者。
重复同步转发只刷新当前 Source 引用；幂等 publication 重试不新增一次测量。

原 v1 daily 的非去重统计仍供其既有消费者使用；BXX 原有去重规则不变。
两种 v1 展示策略的 TopN 信息放在同一 daily 行中，Viewer 适配器明确选择自身策略。
旧 v1 非去重数值不会误当成 BXX 去重基准，也不会为了补齐旧基准还原历史。

每日行保留原有 `capturedAt/rating/dimensions/sampleCount/origin/computedAt`。
新增可选 `bxx` 字段，包含当前 TopN 测量、当前成绩摘要及 immutable current SHA、
上一更新的扁平测量和当天首次扁平测量。仅保留近30日的这部分额外信息；
更早日期的原六维和 Rating 数值保持完整。额外信息不会递归携带上一份归档。
单份详情限1 MiB，继续受既有 daily 文件8 MiB上限和命名空间锁约束。

查询在同一 Source 读取租约中捕获当前成绩和这些数值；原权限初检、绑定观察和
发送前复核保留。上次比较绑定当前成绩摘要及 immutable current SHA，避免保存失败后
误用旧变化。u0 额外绑定成员顺序及档案来源，变更后不复用旧组合的私人测量。
u0 的 BXX 首次物化只读成员当前成绩，不重建成员历史，也不删除已有合并历史。

## 已有数据

旧格式已经覆盖的当日中间测量不会从原始成绩历史反向补造。
单曲和其他 TopN 的缺失详情随后续正常更新积累；独立长期趋势归档继续保留原语义。
