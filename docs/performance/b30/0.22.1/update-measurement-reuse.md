## 对比语义

- 近30日增长：当前数值减去查询当日及之前29个自然日内最早的有效测量。
  新格式保留窗口首日第一次测量，避免当天后续更新覆盖基准。
  图上名称从“近30日区间”改为“近30日增长”，支持显示负值。
- 本次增长：当前六维、Rating 减去紧邻的上一次更新测量，同日多次更新也独立比较。
- NEW：当前 TopN 相对上一份 TopN 新进入的谱面；单曲提升比较同一谱面的 Rating。
  总 Rating 相同也检查榜单和六维，不依赖四舍五入后的显示值判断。
- 缺失对比信息时不显示对应变化，不将全部歌曲标为 NEW，不触发历史补算。

原 v1 daily 的非去重统计仍供其既有消费者使用；BXX 原有去重规则不变。

单份详情限1 MiB，继续受既有 daily 文件8 MiB上限和命名空间锁约束。

查询在同一 Source 读取租约中捕获当前成绩和这些数值；原权限初检、绑定观察和
发送前复核保留。上次比较绑定当前成绩摘要及 immutable current SHA，避免保存失败后
误用旧变化。u0 额外绑定成员顺序及档案来源，变更后不复用旧组合的私人测量。
u0 的 BXX 首次物化只读成员当前成绩，不重建成员历史，也不删除已有合并历史。

### 结论边界与后续迭代口径

当前常规样本表明历史处理和数据准备已降至约0.11～0.14秒，主要等待转向绘图和
QQ 上传/发送。样本是自然请求，未记录玩家身份、成绩量或历史规模，无法匹配相同输入；
0.21.3到0.22.1之间还有其他版本，不能把组间降幅全归因于这一次提交，
也不据此承诺固定加速比或 p95。计时起点是 adapter 分发事件，终点是发送 API
成功回执，不是手机发出消息到客户端实际显示图片。

后续版本沿用 `scripts/performance/collect_latency.py` 采集数字日志，使用现有
内存隔离包装器，`--since` 指定带时区的部署起点，输出到新的临时文件；
按版本、平台、群聊/私聊、TopN、评分版本、指定维度和动态模式分组，初始化另列。
保留全部原始样本、精确时间、分组请求编号和每请求区间并集，汇报中位数、范围和条数，
不将多次采集相同请求的记录重复计数。复用当前测量口径时对照
`latency-comparison.json` 的 `method`、`groups` 和 `observations`，新版本另存目录，
不要覆盖这一组基线。
