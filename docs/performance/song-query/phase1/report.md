# 公共歌曲查询热路径：第一阶段性能证据

日期：2026-11-13（Asia/Shanghai）。基线为最新 main `58174b5100a4f33800976b879abfab5ed1b77b9f` / 已安装 Bot 0.23.0、Application 0.9.1。候选为本提交的 Bot 0.23.1、Application 0.9.2。

本报告只衡量离线命令执行与中心端 `brief()`；不包含跨游戏前置路由、图片读取/落盘、QQ 请求或客户端拉图。没有生产部署，也不把离线收益当作线上回复耗时收益。

## 环境与方法

- 同一宿主机、Python 3.11.4、Linux 5.10.0-16-amd64、fuzzywuzzy 0.18.0 的纯 Python SequenceMatcher；未安装或替换 Levenshtein。
- 中心端使用已安装 Core 0.1.1；客户端前后均加载仓库固定的 Core 0.1.2，未改变两端可见性和分组规则。
- 所有负载串行经过现有 memory QA runner：MemoryHigh 2 GiB / Max 3 GiB、SwapMax 256 MiB、CPUQuota 200%、15 分钟/任务。单进程、单请求顺序回放，没有压生产服务、丢弃系统页缓存或并行构建。宿主机有正常业务负载，P95 是本次观测，不是 SLA。
- 每端每版本 11 类主样本 × 40 次 = 440 次；额外真实部分曲名 40 次。前后各 960 次，共 1,920 个计时样本。每个用例先预热一次；P50/P95 取 nearest-rank。墙钟 perf_counter_ns、CPU process_time_ns。
- 分阶段计时和逻辑文件 open/stat 计数单独回放，未混入主要延迟样本。读次数不代表物理磁盘 IOPS；操作系统页缓存保持自然状态。
- 内存来自独立进程的 smaps_rollup RSS/PSS；额外 tracemalloc 进程估算首个查询后净保留 Python 分配量，其跟踪开销不混入延迟和未跟踪 RSS/PSS。

## 正确性与更新边界

- 真实曲库每端 16,111 个不重复的曲名/ID/别名查询，共 32,222 次逐项差分；另有 120 次真实曲库阶段/开关组合差分，全部一致。
- 保留原未索引 query_music 作为独立差分路径；未改变精确曲名 → ID → 精确别名 → 标准化曲名/别名 → 同音 → 部分曲名 → 模糊匹配的顺序、候选顺序、分数和模糊并列取首规则。
- 保留完整难度前缀精确词优先、中心端同曲分组和客户端可见性/不同版本 ID。
- 请求从 execute_song 的前缀重试到 await deliver/brief 固定一个快照；ContextVar 的 finally 复位，线程和交错异步请求互不借用快照。
- 文件签名包含 dev/inode/size/mtime_ns/ctime_ns。正常写入签名变化在下一请求立即加载；同 tick 原地改写且完整签名相同的极端情况，最长 30 秒后内容复核发现。损坏的相同版本在此期间不重复解析，恢复/原子替换能触发重载。
- writer lock 串行准备，构建前后复核两个文件，最多重试两次，再以单个不可变对象发布。加载失败保留该 root/profile 的旧快照；没有旧快照时沿用 queryMusic 调用失败的命令结果。持续写入耗尽重试后，下一请求仍重试，不能永久封禁一个尚未验证的新版本。
- 原子性指读者得到完整快照，不代表上游两个独立文件具备跨文件业务事务。revision 明确包含两份内容哈希；未更改上游公共数据发布协议，未增加磁盘 last-good 副本，进程重启后仍需要有效输入。

## 复现与证据

冻结目录只包含两份公共曲库，未提交歌曲资源。准备、主基线、完整验证分别执行：

```bash
QA=/home/sigaer/taiko/taiko-forum/scripts/memory/run_qa.sh
PY=/opt/taiko-bot/releases/0.23.0/bin/python
RUN=scripts/performance/song_query/run.py
FIX=/var/tmp/taiko-song-query-replay/catalog
OUT=/var/tmp/taiko-song-query-replay
bash "$QA" "$PY" "$RUN" prepare --fixture "$FIX" --public /home/sigaer/taiko/songs
# 必须先核对新曲库哈希；不同输入不能直接复现本报告数字。
# 按 center / client 分别运行 baseline benchmark；client 需加 --core-source。
bash "$QA" "$PY" "$RUN" benchmark --source /opt/taiko-bot/releases/0.23.0/lib/python3.11/site-packages \
  --fixture "$FIX" --profile center --output "$OUT/before-center.json" --repetitions 40
bash "$QA" "$PY" "$RUN" benchmark --source /opt/taiko-bot/releases/0.23.0/lib/python3.11/site-packages \
  --fixture "$FIX" --profile client --core-source packages/sakura-taiko-core/core \
  --output "$OUT/before-client.json" --repetitions 40
bash scripts/performance/song_query/verify.sh "$FIX" "$OUT"
# REAL_QA / CENTER_QA / CLIENT_QA 填入本次测试输出的对应 QA run ID。
bash "$QA" "$PY" scripts/performance/song_query/validate.py --work "$OUT" --source "$PWD" \
  --test-runs "$REAL_QA" "$CENTER_QA" "$CLIENT_QA"
bash "$QA" "$PY" scripts/performance/song_query/report.py --work "$(dirname "$FIX")" \
  --output docs/performance/song-query/phase1
```

仓库内 before/after JSON 包含全部原始计时、CPU、阶段计数、实际命令返回和 QA run ID；trace 记录每轮 query 的 mode 与选项。QA vault manifest 保存退出和子进程清理状态；附加资源文件保存 cgroup 配额、memory.events 和进程最大 RSS。该内核不支持 memory.peak 时明确记为 null；早期主基线仅有进程最大 RSS，未记录 cgroup 峰值或 OOM 计数，不能据此声称 cgroup 峰值下降。测试结果和 QA 资源摘要见 [validation.json](validation.json)。

静态谱面 Manifest 与官方 QQ Markdown URL 快速路径仍是下一阶段独立设计；本阶段未修改 QQ 全局发送、BXX 或动态图片缓存，也没有资源公开/HTTPS/QQ 兼容性的实施结论。
