# u0 旧存储迁移与运行版本修复

## 原因

旧成绩仍存在于兼容 current/history 文件，未登记 canonical publication；u0 的多成员读取要求每个成员都有 publication。已有旧 u0 也必须显式迁移，否则首次物化会拒绝覆盖旧历史。2026-10-31 只读检查发现 84 组多绑定中 78 组包含未迁移成员，87 个不同成员、26 个旧 u0 需要纳管；其中一个成员缺少 current，不能制造空成绩代替。

Viewer 另有历史 systemd drop-in 固定 Python 0.16.3。Bot 部署现在安装末序 drop-in，统一使用 `/opt/taiko-bot/current/bin/python`；Viewer 的重启仍由其标准部署脚本执行。

## 显式迁移

在私有 JSON 文件列出待迁移的真实成员和已有 u0 identity，文件不得提交 Git。以下命令默认只检查，不构造 store、不创建锁或目录：

```sh
/opt/taiko-bot/current/bin/python -I -m taiko_bot.cli.adopt_publications \
  --root /absolute/userdata --identities-file /absolute/private/identities.json
```

停止所有旧版、不遵守 Source EX 协议的 Writer；确认保留的 Writer 已使用同一 root 和 PublicationStore 锁。随后原命令增加 `--apply --writers-coordinated`。不能将该迁移挂在查询、启动或 HTTP 请求上自动运行。

工具顺序取得单 Source EX，原样复制 current/history 到内容寻址对象并登记 sequence 0，保留原文件、mtime/ctime 和已有 daily。已有 canonical publication 仅验证，不倒退、不重新采信兼容文件。中断可重试；失败的对象阶段不会发布半份 manifest。源文件大小、数量、总字节和批次容量均有上限，迁移需额外磁盘余量。缺少 current 的成员仅计数，等待该账号正常上传/同步，不删除绑定。

迁移不会修改绑定、可见性、真实成绩或重建历史。Native u0 仍包含 manual；远程 u0 仍只使用 CN/JP。新建 u0 的冷历史重建和远程历史响应仍遵守原有 32 MiB 限制，不能以跳过历史、扩大上限或回退未验证文件掩盖错误。

## 验证

39 项定向测试通过，包括原生 u0 切换适配器、未纳管拒绝、显式迁移后增量合并、旧历史/无效证据/daily/时间保留、重复执行、中断重试、symlink 拒绝和 canonical 损坏拒绝。测试仅使用合成文件。

安装后的 0.19.1 另通过 17 项真实 HTTP/隔离 SQL 测试（`mergedSourceSql`、`legacyDeveloperBotSql`），实际数据库为 `viewer1_security_test`，显式开启测试写入；覆盖 u0 current/history、304、权限撤销、损坏拒绝以及 Developer Token 与 v1 ResourceGrant 分离。私有证据：`qa-4c278c3aa4d8`、`qa-1236de227bde`。
