# 趋势查询自动登记已有成绩（0.19.5）

2026-11-06 两次官方 QQ 趋势请求在 daily archive 提交处抛出
`Daily mutation requires an active canonical Source`，未向用户回复。
只读核查确认两个绑定均为单账号，当前成绩和历史存在，但没有 committed.json。
10 月 31 日迁移记录只覆盖 u0 及其成员，不是全部单账号。

本次产品要求明确：有成绩的账号都应正常使用，不要求用户手动迁移或更新成绩。
因此替代历史“仅显式维护可 adopt”的查询侧限制：趋势准备在绑定校验后，
先对实际 Source 自动登记已有原始成绩，再进入统一的读取、计算、归档流程。
单账号、合并账号成员及已有合并输出均处理；没有临时出图不保存的分支。
成绩 JSON、原文件、历史数值、可见性和绑定保持不变。

登记复用 PublicationStore.adopt，Source SH 探测后释放，再取得 EX 并复核授权和
提交清单，避免锁升级及覆盖并发 Writer 的新提交。当前生产 Writer 已统一使用
同一 Source EX（见 u0-recovery-20261031.md）。不扫描或批量改写其他账号。
空账号不生成空清单；已有提交、删除 tombstone 和损坏清单不回退旧文件。
历史文件存在但缺 current 时也能登记并查询历史。

PublicationError 经绑定权限复核后转换为简短错误回复，不向用户输出内部路径。
合成回归覆盖自动登记及重复查询、原成绩保留、每日归档新增与历史冻结、
无 current 的历史、单账号/u0 Provider 接线、删除/损坏/授权撤销以及异常回复。
